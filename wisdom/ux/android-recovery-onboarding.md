# Android: failed speech and first voice setup

## Decisions

- Keep the inherited enable/select-keyboard wizard. Voice setup lives inside the existing Speech provider page, reached from keyboard voice input or voice settings. No second keyboard wizard, account, mode, analytics, or history archive.
- Existing Groq/OpenRouter defaults, key links, encrypted key storage, and refinement settings remain authoritative. Already configured users get an optional setup button, not a forced flow. Setup never resets provider settings.
- Three short steps: provider/destination disclosure and Save and continue; Android microphone permission; a real test using the same recorder and remote final backend. The test displays text only, never creates an editor transaction. Normal keyboard insertion and Cancel/live-preview behavior are explained. Back and Leave are native buttons; step, leave/reopen state, test readiness, and completion persist separately from credentials. Saving provider setup again invalidates test readiness.
- Failed final audio is one PCM packet in app-private, backup-excluded storage. Successful recordings and explicit recording cancellation are not archived. New dictation/test capture is gated by Retry / Discard while a failure exists. File writes are atomic; separate components cannot overwrite a saved packet. Retry result acknowledgement and metadata updates use the packet ID so an old request cannot delete or change newer failed speech.
- Retry loads current provider settings. Credentials (401/403), network reachability/timeouts, quota (429), and other provider failures use plain distinct copy, without echoing raw provider bodies. Retry failure updates the saved cause without changing audio. Retry success clears audio only after the active component receives the result. Leaving/cancelling a pending retry preserves speech.
- Recovered text is never automatically committed to the captured editor. The keyboard offers Insert here (creating a new transaction at the explicit click), Copy, and Done; settings offer Copy/Done only. Result text is session-only, not an archive.

## Lifetime and preview audit

- Android 13+ preview remains conditional on an installed, supported on-device recognizer. Final transcription remains remote, and refinement failure still falls back to raw text. No network preview or model-download fallback was added.
- Existing on-device preview close invalidates its session before destroying the recognizer, rejecting late partial callbacks. Keyboard close and failure discard provisional text; the existing editor transaction restores the original selection when a preview replaced it, and a finished transaction rejects subsequent updates.
- Final recognizer delivery now stays inside its cancellable model job instead of launching a detached lifecycle-scope callback. The settings test cancels/releases recording on Back, navigation/disposal, and activity stop. Recovery requests use a composition-owned scope and disconnect on disposal.

## Tool/build blockers and limits

- Initial build version fallback expected a `master` ref and produced -1; explicit VERSION_CODE/VERSION_NAME fixed configuration without changing the build file. An initial Kotlin test inferred a Boolean return, which JUnit rejected; corrected and rerun successfully.
- Gradle connected-test execution was blocked offline by uncached `com.android.tools.utp:android-test-plugin-host-additional-test-output:31.13.2`. Direct adb instrumentation ran successfully instead. The read-only emulator initially had an older app installation; downgrade and storage restrictions required replacing that app only inside the disposable snapshot. No persistent AVD changes were saved.
- After `pm clear` with this IME already selected, one cold launch stalled at the splash screen. Switching to the other IME, launching the inherited wizard, then selecting OpenWispr normally rendered setup and allowed the checks above. The collected thread dump shows the main thread blocked in inherited LatinIME.onCreate → Subtypes.addDefaultSubtypesIfNecessary → SettingsKt.setSettingBlocking, before recovery/setup code. Root cause is not established; a clean cold-start/IME lifecycle check remains important before release. Evidence is in /tmp/openwispr-android-startup-trace.txt and /tmp/openwispr-android-bugreport.zip (not committed).
- No valid live provider key or physical microphone was used. Successful real-speech/provider end-to-end insertion, Copy, selection restoration, installed local-preview model behavior, Bluetooth capture, and process death during capture/upload still need device validation. Tests use real storage/coroutines and fake provider responses; emulator retry sent only the synthetic fixture with an invalid key. This feature recovers completed failed final requests, not recordings interrupted before failure can be saved. Disk-write failure is reported honestly rather than claiming saved audio.
