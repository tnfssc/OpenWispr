# Values

## Make dictation easy, not bigger

The user wants small features and puts user experience first. Favor changes that make speaking, stopping, and getting text easier. Do not add a new screen or mode unless the gain needs it.

Use this to choose dictation UX work. It does not mean skipping a change that prevents lost work.

Source: [competitor UX research](ux/competitor-research.md), user brief.

## Tell people where their speech goes

Remote audio and cleanup text go to the selected provider. Say that plainly. Do not call remote processing local or private. Keep paste behavior clear and let people cancel before insertion.

Use this for setup, provider changes, and recording UI. It does not require repeating a long warning on every recording.

Source: [provider guide](../docs/providers.md).

## Share the flow, not every implementation

The native clients share a dictation contract, not a code library. Borrow the same helpful idea where it fits. Do not force desktop controls into the Android keyboard.

Use this for cross-platform UX choices. It does not rule out a shared library if a later task shows a real need.

Source: [architecture](../docs/architecture.md).
